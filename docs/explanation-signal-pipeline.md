# 신호 파이프라인 설계 해설

뉴스 기사 한 건이 Telegram 알림으로 전달되기까지의 경로와 각 단계의 설계 의도를 설명합니다.

---

## 전체 흐름

```
RSS 수집 → 중복 필터 → 본문 크롤링 → LLM 요약
    → LLM 신호 감지 → 티커 심볼 해석 → DB 저장
    → 게이팅 판정 → HIGH CONFIDENCE 상향 → Telegram 발송
```

각 단계는 실패해도 다음 기사 처리를 막지 않습니다. 워커가 계속 대기하므로 개별 에러는 로그에 기록되고 넘어갑니다.

---

## 1. 수집 vs. 처리 분리

`run_scheduler.py`의 두 핵심 루프는 asyncio Queue를 사이에 두고 완전히 분리됩니다.

```
collect_job()          → Queue → summary_worker()
(15분 주기, 빠름)                  (느림, LLM 처리)
```

**왜 분리했나:** LLM 호출은 수 초~수십 초가 걸립니다. 수집 루프가 LLM을 직접 호출하면 수집 간격이 밀립니다. Queue를 통해 수집과 처리를 독립시키면 수집이 항상 제시간에 실행되고, 처리는 처리 가능한 속도로 소화합니다.

**트레이드오프:** 기사가 갑자기 많이 들어오면 Queue가 쌓입니다. 신호 발송이 수집보다 늦어질 수 있습니다. 심각한 뉴스 이벤트에서는 알림이 수십 분 지연될 수 있습니다.

---

## 2. 중복 방지 (url_hash)

```python
h = _url_hash(art["url"])   # SHA-1 앞 16자
if h in _seen_hashes:
    continue
```

`_seen_hashes`는 인메모리 set입니다. 재시작 시 DB에서 최근 해시를 로드해 복구합니다. 이 구조는:
- 재시작 후에도 중복 처리 방지
- 피드가 같은 기사를 반복 제공해도 방어

URL이 동일하면 내용이 달라도 같은 기사로 취급합니다. 수정 기사가 별도 URL로 오지 않으면 놓칠 수 있습니다. 이 트레이드오프는 의도적입니다 — 중복 알림이 놓친 수정 기사보다 유해하다고 판단했습니다.

---

## 3. LLM 신호 감지와 티커 심볼 해석

LLM은 JSON으로 신호를 반환합니다:

```json
{
  "direction": "BUY",
  "strength": 4,
  "reason": "2분기 영업이익 전망치 30% 상향",
  "tickers": [{"name": "셀트리온", "symbol": "068270.KS"}],
  "article_type": "earnings"
}
```

LLM이 종목 심볼을 정확히 제공하지 못하는 경우가 있습니다 (잘못된 코드, 빈 symbol 필드). 이 경우 `_parse_signal_json()`이 3단계로 해석을 시도합니다:

```
1. ticker_cache.resolve(name)     → KRX DB 정확 매칭
2. ticker_cache.resolve_fuzzy(name, threshold=0.82)  → 근사 매칭
3. 모두 실패 → _resolution_misses[name] += 1 (진단 카운터)
```

**fuzzy 임계값 0.82의 근거:** "현대차"(6자) vs "현대차증권"(8자)의 SequenceMatcher ratio ≈ 0.75 < 0.82입니다. 이 쌍은 false positive가 발생하면 안 되므로 0.82를 하한선으로 설정했습니다. "셀트리온헬스케어" vs "셀트리온헬스케어(주)"는 ratio > 0.82이므로 정상 매칭합니다.

## 4. 게이팅 시스템

게이팅은 신호를 억제하는 필터입니다. `is_actionable`을 통과한 신호도 관련 종목이 등록되지 않으면 Telegram에 전달되지 않습니다.

```
신호 발생
    ↓
[게이팅 캐시 있음?]
 아니오 → 그대로 전달 (초기 실행 방어)
 예
    ↓
[관련 종목 있음?] (ticker_symbols 비어있으면 = 거시경제 기사)
 아니오 → 그대로 전달
 예
    ↓
[스크리너 교차?]  ← Ichimoku 주봉 통과 종목과 심볼 일치
 예 → HIGH CONFIDENCE로 상향 후 전달
    ↓
[Stage 활성?]    ← 최근 7일 이내 Stage 1/2/3 분류 종목과 심볼 일치
 예 → NORMAL 신뢰도로 전달
    ↓
 아니오 → 억제 (로그만 기록)
```

**두 캐시의 역할:**

| 캐시 | 갱신 시점 | 의미 |
|------|----------|------|
| `_screener_tickers` | 매주 일요일 스크리닝 완료 시 | 이번 주 Ichimoku 주봉 통과 종목 |
| `_active_stage_tickers` | 매일 일봉 분류기 완료 시 | 최근 7일 이내 Stage 1/2/3 분류 종목 |

**왜 이중 레이어인가:** 주봉 스크리너는 한 주에 한 번만 갱신됩니다. 스크리닝 직후에 Stage 1이 발동한 종목은 다음 주 일요일까지 스크리너에 없습니다. Stage 7일 레이어가 이 간극을 메웁니다. "스크리너에 없지만 지금 Stage 1 랠리 중인 종목"의 뉴스 신호를 놓치지 않습니다.

**거시경제 기사 예외:** `ticker_symbols`가 비어있는 신호(금리 인상, 환율 변동 등 종목 무관 기사)는 게이팅을 통과합니다. 종목 특화 게이팅을 거시 이벤트에 적용하면 투자 결정에 중요한 정보를 차단하게 됩니다.

## 5. HIGH CONFIDENCE

스크리너 통과 종목의 뉴스 신호는 `signal.confidence = "HIGH"`로 상향되어 Telegram에 🔥 배지와 함께 발송됩니다.

```
🔥 HIGH CONFIDENCE — 스크리너 교차 종목
🟢 매매 신호 감지 - BUY
강도: ⬛⬛⬛⬛⬜ 4/5
```

**의미:** 해당 주 주봉 차트 분석(Ichimoku 7조건)을 통과한 종목에 동일 방향의 뉴스 신호가 발생했다는 뜻입니다. 기술적 분석(차트)과 기본 분석(뉴스)이 같은 방향을 가리킵니다. 두 신호의 교차가 단일 신호보다 실제 주가 움직임과 연관성이 높다는 것이 이 시스템의 핵심 가설입니다.

**경고:** HIGH CONFIDENCE는 "확실한 매수 신호"가 아닙니다. 두 독립 신호의 동시 발생을 뜻합니다. 투자 결정은 사용자가 직접 판단해야 합니다.

---

## 6. 스크리너-우선 아키텍처의 트레이드오프

이 게이팅 시스템은 다음을 포기합니다:
- **미스 가능성:** 스크리너 미통과·Stage 비활성 종목의 뉴스 신호는 무시됩니다. 실제로 중요한 이벤트일 수 있습니다.
- **진입 지연:** 스크리닝은 주 1회입니다. 스크리닝 직후 발생한 종목은 최대 7일 후에야 스크리너에 등록됩니다 (Stage 레이어가 완충).

대신 얻는 것:
- **노이즈 감소:** 2770개 KRX 종목 중 차트·수급 기준을 통과한 소수 종목에만 집중합니다.
- **신뢰도 상승:** HIGH CONFIDENCE는 두 독립 필터를 모두 통과한 신호입니다.
